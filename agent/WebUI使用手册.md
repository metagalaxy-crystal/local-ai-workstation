# 自研 Web UI 使用手册

> 本地模型工作站的一体化控制台：任务对话 + 多模型流水线编排 + 系统监视。
> 标准库 `http.server` 实现，零前端依赖。默认地址：`http://127.0.0.1:8088` ｜ 更新日期：2026-10-25

相关文档：[agent/README.md](README.md)、[RooCode接入手册.md](RooCode接入手册.md)、源码 [webui.py](agent/webui.py) / [orchestrator.py](agent/orchestrator.py) / [services.py](agent/services.py)

## 一、启动

```powershell
cd d:\models\agent

# 推荐启动：Web UI + 运行看板（看板 :8090 默认就会启动）
d:\models\.venv\Scripts\python.exe -m agent.cli --webui

# 不想开看板（例如 8090 被占用）
d:\models\.venv\Scripts\python.exe -m agent.cli --webui --no-monitor
```

> 看板已默认启动，**不需要再加 `--monitor`**（该参数已移除）。`--check` / `--tools` 这类一次性命令不会启动看板。

> 调度器已内置在 WebUI 里，**不需要再加 `--scheduler`**（加了也会被自动忽略，不会重复触发）。`--scheduler` 只用于不带 `--webui` 的纯 CLI 模式。

停止：终端按 `Ctrl+C`。改端口：编辑 `configs\agent.json` 的 `webui.port`。

> 启动不再自动创建空白会话：CLI 显示「会话 未创建（首次输入后建立）」，首次输入才落库；`/new` 也只是重置草稿。

> 与旧版不同：**启动不再要求 llama-server 在线**。模型服务可以在页面侧边栏随时启动/切换。

**主题**：右上角按钮切换浅色/深色，默认浅色，选择记入浏览器 localStorage。

## 三、任务（会话）管理

- **每个任务一个沙箱**：`agent\memory\workspace\<session_id>\`。任务的输入、产出、附件、向量库全部在里面，不再有单独的输出目录，也不再让用户手填工作目录
- **小标题**：任务列表只显示一行小标题（超 16 字按标点截断，旧任务同样压缩），第二行是 `沙箱 <session_id>`；不显示长路径
- **新建任务**：「+ 新建任务」只进入草稿态（不写库、不建沙箱），发送第一条消息时才创建会话；启动时自动清理历史遗留的空白会话（0 消息、0 运行）及其空沙箱
- **删除任务**：悬停任务条目点 `×`，连消息、运行账本、**保存的运行图**和整个沙箱目录一起删除
- 文件类工具的相对路径都按该任务的沙箱解析；上传附件存到沙箱的 `uploads\` 子目录

## 四、两种执行方式

### 1. 发送（普通对话）

发送后立即返回、后台执行，**每一步决策都实时显示在页面顶部的模型运行图和消息流里**，不再"黑箱等结果"：

- **模型运行图**（顶部步骤条）随对话过程动态出现节点：
  `◆ 决策·用哪个模型 → ⚙ 服务切换（换模型时）→ ◉ 对话模型·逐轮推理 → ⚒ 工具调用 → ✔ 完成`
- **消息流**同步刷出详细过程事件（0.8s 轮询）：
  - `◆ 决策`：选了哪个模型、为什么（`模型选择 → qwen36：重任务 → 旗舰质量` 或 `沿用当前模型 nanbeige`）
  - `⚙ 服务切换`：换模型的全过程（`切换模型 nanbeige → qwen36（加载中…）` → `qwen36 就绪`）
  - `◉ 第 N 轮推理`：每轮的 prompt/completion token 数实时累计
  - `⚒ 工具步骤`：每步一行摘要（工具名 · 参数 · 成功/失败 · 耗时），点「详情」在右侧看完整入参出参
  - 最后一条助手消息附总 token 统计（轮数 / tokens / 停止原因）
- **回复逐字流式输出**：模型生成的文本实时累积在消息流末尾的"活气泡"里（蓝框 + 闪烁光标），边生成边看，不用等整轮跑完；生成结束活气泡变成正式回复
- 工具调用在消息流里**每步只占一行**（工具名 · 参数前 80 字 · 成功/失败 · 耗时），点「详情」在右侧预览看完整入参和结果；思考过程也折叠成一行「💭 思考过程 N 字 · 点击查看」；收尾显示 `✔ 完成` / `✖ 失败原因` 节点

也就是说：**模型此刻在想什么、用哪个模型、调到什么工具，页面上一目了然**。执行中可点步骤条右侧「取消」。

### 2. 规划执行（多模型流水线，重量级任务用）

点「规划执行」后进入流水线模式：

1. **规划**：LLM 先产出「模型运行图」——页面顶部出现步骤条，如
   `1.写大纲·none → 2.写分镜·none → 3.出图·generate_image → 4.配音·tts_speak → 5.汇总·none`
2. **逐步执行**，编排器按步骤类型自动切换本地服务（显存互斥硬约束，先停后起）：

   | 步骤类型 | 服务动作 |
   |---|---|
   | 文本步骤（tool=none） | 停 ComfyUI → 确保 LLM 在线 → 跑独立 AgentLoop（可用文件等工具，产出落盘） |
   | 出图/视频/音乐 | LLM 先生成工具参数 JSON → **停 LLM → 起 ComfyUI** → 直接调工具 |
   | TTS/ASR | 停 ComfyUI + 停 LLM（语音脚本跑完自释放显存）→ 调工具 |
   | MCP 步骤（tool=mcp_*） | LLM 保持在线产参数 JSON → 直接调工具（CPU 子进程，不动 GPU 服务） |

   > 文本步骤与会话历史**隔离**：每个步骤不带历史、内部轮次不写会话，步骤间靠产出摘要传递；步骤结束时只把一条「步骤结论」写进消息流。避免长流水线把上下文越背越大。

3. 消息流实时显示：服务切换事件（黄边）、每步工具入参/出参（蓝/绿/红边）、每步 token 用量
4. 完成后自动**恢复对话环境**（停 ComfyUI、重启原 LLM），可继续普通聊天

执行中可点步骤条右侧「取消」（在步骤间生效，打不断正在跑的单个工具）。

### 3. 模型运行图 · 展开视图（看步骤 / 用量）

点运行条右侧「展开」进入四列框图：

- **任务概述**：目标、状态、运行号、耗时
- **模型调度**：决策来源、每个模型的轮次与 token
- **步骤与工具**：对话按「第 N 轮」、流水线按「计划步骤」列出**大步骤**，每行只有短标题 + 一行摘要（工具名 · tok · 耗时）。子节点**默认折叠**，不再一次全铺开：
  - **点大步骤** → 展开视图会自动打开并选中该步（运行条 / Token 列 / 步骤列点击效果一致），该步高亮、子节点展开，同时右侧预览显示整步汇总；**再点一次收起**
  - **点「推理 · 第 N 轮」子节点** → 预览本轮 token 构成（prompt + completion），展开视图里该轮高亮
  - **点「工具 · 工具名」子节点** → 只看这一次调用：完整参数、完整结果、该步上下文；展开视图里该次调用高亮
  - 三处视图（运行条 / 展开视图 / 预览面板）始终指向同一选中范围，点哪都能同步定位（按工具聚合时会同时选中多个步骤）
- **Token 消耗**：本次运行总量 + prompt/completion 构成条；下面「按大步骤」逐行给出每步 token 和占比条

顶部运行条上的节点也都是可点的：

- **工具 chip**（如 `⚒ web_search ×5`）→ 右侧预览给出该工具汇总（调用几次、成功/失败、总耗时、涉及几个步骤几轮推理、合计 tokens）和逐次调用入口；同时展开视图把这个工具出现过的**所有步骤一起展开**（不是只展开第一个），其中每条同名工具调用行蓝色高亮，并把第一个出现位置滚进可视区；该 chip 本身也变成蓝框选中态
- **「◉ 对话」chip** → 预览列出本次对话每一轮的工具与 token（点某轮可直接定位），展开视图同时展开全部轮次
- **流水线步骤 chip** → 该步骤明细

**点任意步骤**（步骤列或 token 列都行）→ 右上方预览面板显示该步精简明细：状态、耗时、本步 tokens（prompt/completion）、目标/工具、每次工具调用的参数与结果（超长自动截断）、产出摘要或错误；被选中的步骤卡片蓝色高亮。

运行条右上角的 **「任务 tokens N」是整个任务的累计**（历史所有运行 + 本次正在跑的实时用量），悬停可看本次 prompt + completion。

**运行图会自动保存**：每次运行（对话或流水线）的计划、事件流、每轮/每工具 token 都写进 `memory\session.db` 的 `run_graphs` 表（运行中每 1.5 秒节流刷新，结束时强制写一次）。所以刷新页面、关掉 WebUI 再打开、甚至换台机器连同一个库，都能重新看到这幅运行图和逐节点 token。

- 打开任务时默认恢复**最近一次**运行图
- 点运行条右侧 **「◷ 历史」** → 列出本任务历次运行（时间、任务、状态、tokens），点任意一条即可回看当时的完整运行图
- 同一次运行的 token 也会写进 `runs` 账本（流水线现在也记账），`/api/usage` 和看板统计不会再漏掉流水线开销；做规划/验收评估时可直接取这两处数据
- 删除任务时，其保存的运行图一并删除；内存里每个任务只保留最近 30 次已结束运行（更早的仍可从库里按 run_id 回看）
- **老运行自动补档**：WebUI 启动时会读 `trace.jsonl`，把上线持久化之前、trace 里仍有记录的运行还原成运行图（事件、逐步 token、失败状态；原始回复正文未单独留档会标注说明）。trace 已轮转/清掉的老运行无法追溯，只剩 `runs` 账本里的汇总 token
- **上次没跑完的运行自动标为「中断」**：WebUI 重启后，把账本与运行图里残留的 `running` 状态改成 `interrupted`，不会再出现永远转圈的任务
- **报错同样留档**：模型调用失败、LLM 离线、上下文超限、流水线步骤失败等都会以 `⚠ …` 写入会话历史（刷新/重启后错误气泡不会消失），并记入运行账本 `runs.error`。运行图里保留完整的 `error` 事件和失败工具的参数/结果；「◷ 历史」列表里每条失败运行下方直接显示报错原文（截 300 字），点开可定位到具体失败节点

### 任务验收与重修

任务跑完后会自动做一次**验收**：用一个模型独立检查"是不是真的做完了"，不共享执行过程的上下文，避免自己给自己打高分。

- 验收作为流程图里的一个节点出现，名字是 **「验收」**，点开能看到得分、问题和整改建议
- **不达标会自动重修**：验收返回 `redo_from`（最该重做的那一步），流水线从该步开始重跑，前面的步骤成果保留
- 最多重修 `verify.max_retry` 次（默认 1），仍不通过就保留结果并标注"验收未通过"
- 对话任务只在**调用过工具**时才验收，纯问答不做额外检查，避免每次聊天都多跑一次模型；验收时会把沙箱最近产出文件列表一并交给验收模型，判断"文件是否真的产出了"

配置（`configs\agent.json`）：

```json
"verify": { "enabled": true, "max_retry": 1, "model": "qwen36" },
"loop": { "max_wall_time_sec": 1800, "max_total_tokens": 200000 }
```

`model` 默认 `qwen36`（注册表定位即「质检/评测」，实测全能旗舰）。验收前会**真的把模型切换上去**、验完切回执行模型（事件流可见切换过程）；留空则沿用当前模型（同模型自检，不推荐）。注意：执行模型不是 qwen36 时，每次验收要多付一次 35B 加载（几分钟）+ 切回，嫌贵可改成 `lfm`（8B、加载快、工具调用干净）做轻量独立验收。
`loop.max_wall_time_sec` / `loop.max_total_tokens` 是单次运行的总预算（0=不限），超限优雅收尾并写入消息流，防止失控任务无限烧；模型调用瞬时失败会自动隔 2 秒重试一次。

## 五、侧边栏服务面板

- **LLM**：显示当前在线模型；模型注册表（`scripts\llama_cpp\models.json`）里每个模型带「切换」按钮——点击后自动停旧模型、启动新模型（35B 级加载约几分钟，看服务日志进度）
- **ComfyUI**：起/停按钮 + 在线状态点（绿=在线，红=离线）
- **Embed :8081 / Rerank :8082**：起/停按钮 + 状态点。这两个是 RAG 后端（Qwen3-Embedding / Qwen3-Reranker，CPU 常驻零显存），知识库与上下文记忆都依赖它们
- **预加载 LLM**：WebUI 启动时后台自动装载 `llm.model` 指定的模型（默认 **qwen36**，35B 旗舰，首次加载需几分钟），打开页面稍等即可对话；`llm.preload=false` 关闭
- **模型选择（默认，零额外开销）**：每条消息发送前按两级本地规则决定用哪个模型，结果显示在消息流里（`模型选择 → qwen36：重任务 → 旗舰质量`）：
  1. **难度启发**：消息含「看图/这张图/识别图/图中/OCR…」→ 多模态（qwen25vl，单词命中即生效，**硬性规则**；注意「图片/照片/截图」这类词不触发——「搜索图片做PPT」是生成任务不是看图任务）；「小说/分镜/长文/代码/深入…」→ 旗舰（qwen36，**需同组关键词命中 ≥2 个**，避免"详细"一个词就触发几分钟的模型加载）；都不命中 → 看下一级
  2. **任务惯性**：沿用本任务上次实际使用的模型（存在任务记录里，重启不丢）；都没有 → 保持当前模型
  3. **迟滞保护**：当前模型已满足规则候选时不切换；距上次切换不足 `router.switch_cooldown_sec`（默认 1800s）时软性规则让位（硬性规则不受限）——35B 级加载几分钟，来回切比用错模型更亏
  规则在 [task_router.py](file:///d:/models/agent/agent/task_router.py) 的 `_RULES`，可自行增删关键词
- **服务日志**：`output\agent\services.log` 尾部，切换过程全程可见
- **MCP 插件**：每行显示 `状态点 + 名字 + 对标软件 + 状态`。绿点=已挂载（后面是工具数），红点=启用但挂载失败，灰点=未启用
  - **初始不挂载任何 MCP**：`configs\agent.json` 里 14 个 server 的 `enabled` 全为 `false`，启动更快、工具清单不挤占上下文
  - **按任务自动挂载**：每次任务开始前，按关键词判断需要哪些 MCP，命中即挂载（常驻复用，不重复启动）。规则在 [mcp_router.py](file:///d:/models/agent/agent/mcp_router.py) 的 `_RULES`，**单任务最多自动挂 2 个**
  - **schema 预算**：工具清单每轮都随 prompt 重发，本地模型上下文有限。自动挂载的 MCP schema 总量超过 `mcp.schema_budget_chars`（默认 6000 字符）时，自动卸载最老的闲置自动挂载项（当前任务需要的和手动启用的不动）
    - PPT/幻灯片/课件 → `deckcraft`；Word/文档/报告 → `wordcraft`；Excel/表格 → `gridcraft`；PDF → `pdfcraft`
    - 修图/抠图/PSD → `photocraft`；矢量/Logo → `vectorcraft`；海报/画册 → `designcraft`；动效/特效 → `effectcraft`
    - 原型/UI/Figma → `figcraft`；视频剪辑 → `filmcraft`；音频/混音 → `soundcraft`；照片库/RAW → `lightcraft`；CAD/图纸 → `cadcraft`
    - 浏览器/网页/爬取/URL → `playwright`
  - 想强制用某个 MCP：直接在侧边栏点「启用」手动挂载，或在任务里写明对应关键词（如"用 deckcraft 做"）
  - **MCP 也是一个调度节点**：MCP 调用走 stdio 子进程，只吃 CPU 不占显存，在运行图里标为 `resource=mcp`，可与 GPU 上的 LLM 步骤重叠执行
  - **已预置 14 个 server**：`playwright`（25 工具）+ 13 个 Craft CLI（`cadcraft` `deckcraft` `designcraft` `effectcraft` `figcraft` `filmcraft` `gridcraft` `lightcraft` `pdfcraft` `photocraft` `soundcraft` `vectorcraft` `wordcraft`），侧边栏点「启用」即时挂载，再点「停用」卸载并把 `enabled` 写回配置
  - Craft 的启动方式就是各自 CLI 的 `mcp` 子命令（stdio），工作目录设为应用目录；`artcraft` / `launcher` 没有 `-cli.exe`，不是 MCP，**侧边栏不列出**
  - **对标软件**（取自各应用 README 的官方定位，显示为名字右侧的灰色标签）：

    | MCP | 对标 | MCP | 对标 |
    |---|---|---|---|
    | `playwright` | Playwright | `pdfcraft` | Adobe Acrobat |
    | `wordcraft` | Microsoft Word | `photocraft` | Adobe Photoshop |

## 六-c、上下文记忆（向量库跟随沙箱）

每个任务的对话上下文会**向量化为长期记忆**，存在**该任务自己的沙箱**下（`memory\workspace\<session_id>\kb\vectors.db`），任务之间互相隔离。注意与左侧「全局知识库」（`memory\knowledge\`）区分：这里是任务内自动沉淀，那里是手动维护、按门类全局生效。

- **归档**：对话超出上下文上限被裁剪时，被裁掉的片段不再直接丢弃，而是向量化写入本任务沙箱的知识库（内容哈希去重）
- **召回**：每次发消息/跑流水线时，用任务文本在本沙箱知识库里检索，相关度达标的片段（默认阈值 0.35、最多 3 条）以「历史记忆」拼进 system prompt——换一轮对话也能记起这个任务之前做过什么
- **文档共库**：`kb_ingest` 入库的文档也在同一个库，所以「把小说原文入库」+「边聊边忘」两套记忆在同一个任务沙箱里统一沉淀
- **依赖**：需要 Embed :8081（必须）和 Rerank :8082（可选，缺失时退化为纯向量召回）在线；侧边栏一键启动，CPU 运行不占显存。服务离线时记忆功能静默降级，不影响正常聊天
- **开关**：`agent.json` 的 `rag.memory`（默认 true）、`rag.recall_top_k`、`rag.recall_min_score`

**上下文硬预算（不再出现 `exceeds the available context size`）**：历史裁剪从"按固定字符数"改为**按估算 token 且对齐模型真实窗口**：

- 窗口大小自动取 `models.json` 里该模型的 `-c`（qwen36 / lfm = 16384，nanbeige = 32768，VL = 8192）；要强制固定就设 `llm.context_size`
- 预算 = 窗口 − 生成预留（`llm.max_tokens`，最多占窗口 1/4）− 工具 schema（含已挂载 MCP）− 余量；中文按 1 字 1 token 估算，宁高估不低估
- **按实测自动校准**：每次调用后拿服务端返回的真实 `prompt_tokens` 与本地估算比，比值（1~4 倍）会用于收窄后续预算，避免 prompt 一路贴到 16384 把生成空间挤成 0
- **同一轮内也会继续压缩**：只按"轮"丢历史丢不动当前这一轮（一次任务里连续十几次大工具结果很常见），现在会在单元内继续二分缩小单条工具结果、丢掉当前轮最早的调用组，必要时硬截断超长输入，并始终保证 `tool_calls` 与 tool 结果成对
- 万一服务端仍然报超出，会自动压缩到 65% 再重试（最多 2 次），并在消息流里提示"已压缩到约 N tokens 后重试"，不会让整个任务直接失败
- **空回答不再算完成**：模型一个字没回（通常就是窗口被占满）时，先收窄历史催一次继续；仍空则标记 `empty_answer` 失败，运行图显示"✖ 空回答（上下文占满，未完成）"，并把原因写进会话，不会假报"✔ 完成"
- `loop.max_history_chars` 保留为额外的字符上限（0 = 关闭），老配置仍然有效

**记忆浓缩（整理记忆）**：片段积累多了之后，可以把流水账蒸馏成长期事实。选中任务后点侧边栏「整理记忆」按钮（或在对话/定时任务里直接说「整理记忆」，模型会调 `memory_consolidate` 工具）：

- LLM 把该任务的归档片段蒸馏成四节记忆卡（设定与事实 / 已定决策 / 当前进展 / 待办与注意），写入沙箱根目录的 `MEMORY.md`
- 记忆卡**无条件注入**每轮 system prompt，不走相似度，且与召回片段冲突时以记忆卡为准
- 记忆卡同时作为 `summary` 块入库参与召回；再次整理时旧摘要整体替换，不叠加
- 整理需要 LLM + Embed 在线；原始片段保留不归并删除

## 八、常见问题

| 现象 | 原因 | 处理 |
|---|---|---|
| 切换模型几分钟没反应 | 35B 级模型加载慢 | 看侧边栏服务日志；超时 600s 会报错 |
| 流水线出图步骤失败 | ComfyUI 没起来 | 服务日志看原因；也可手动先起 ComfyUI 再跑 |
| 端口 8088 被占用 | 旧实例没退干净 | 杀残留 python 进程或改 `webui.port` |
| 语音步骤卡住 | 语音脚本与 LLM 互斥，编排器已先停 LLM | 等脚本跑完；它自己释放显存 |
| 附件找不到 | 存在任务沙箱的 `uploads\` 下 | 任务条目第二行可看到沙箱编号，对应 `memory\workspace\<编号>\` |
| 勾选了知识库却没生效 | 只勾了门类，没开总开关 | 需同时勾选「发送对话时引用全局知识库」和具体门类 |
| 任务少了/文件不见了 | 删除任务会级联删除整个沙箱 | 删除前先确认沙箱里有用的产出已另存 |
| 预览里 docx 只有文字 | `.docx` 为抽取文本预览，保留不了排版 | 需要原样排版请点右下角文件下载后本地打开 |
| 任务只说"我会先…稍等片刻"就结束了 | 模型没调工具，只回了计划 | 已内置自动催促（最多 2 次，运行图里能看到"自动催促继续"的提示）；仍不执行就换支持工具调用的模型 |
| 回复里直接打印 `{"tool": ...}` JSON 就结束了 | 小模型把工具调用当正文输出，没走正式调用通道 | 已内置打捞：JSON 合法且工具已注册就自动转成真实调用（事件流提示"已转为真实调用"）；JSON 损坏则按"只说不做"催促重发 |
| 展开视图里工具参数是空的 | 老版本记录只存了结果没存参数 | 新运行会完整记录参数与结果；老记录只能看到结果 |
| 刷新后运行图 / 报错气泡不见了 | 老版本只存在内存里 | 现在运行图与报错都落库（`run_graphs` / `runs.error`）；确认没有删任务，打开任务会自动恢复最近一次，点「◷ 历史」可回看全部运行 |
| 报错 `request ... exceeds the available context size` | 旧版按固定字符数裁剪，超过模型真实窗口 | 已改为按窗口 − 生成预留 − 工具 schema 计算 token 预算；仍超限会自动压缩重试 2 次，不再整单失败 |
| Ctrl+C 退出时终端卡住、光标不动 | 工具线程卡在 MCP/网络/子进程读取里；旧实现用线程池，worker 是**非 daemon** 线程，Python 退出时会 join 它，于是一直挂着 | 已改为 daemon 线程执行工具（超时后留在后台也不挡退出），退出时先关闭常驻 MCP 会话再 `_exit`；Ctrl+C 现在立即返回 |
| 任务跑完却没有产物，只留下几句过程话 | 模型没把结果保存/导出成文件，或中途上下文爆掉 | system prompt 已要求产出类任务必须落成真实文件并给出路径；空回答现在判失败而不是"✔ 完成"。把任务拆小、减少一次性资料量后重试 |
| 回复是"模型没有返回任何内容"，运行图显示"✖ 空回答（上下文占满，未完成）" | prompt 贴满窗口，留给生成的 token 只剩个位数 | 已修复：同一轮里的工具结果会继续压缩，并按实测/估算比例收窄预算；仍频繁出现就调大 `models.json` 里的 `-c` 或换 32768 窗口的模型 |
