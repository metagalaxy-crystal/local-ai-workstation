**两个重要事实**
1. 每个应用都是 **GUI + CLI 双入口**：`xxx.exe` 开图形界面，`xxx-cli.exe` 无窗口跑批/脚本。CLI 与 GUI 是同一套"命令"（每个按钮背后都是一条有稳定 id 的命令），所以人、脚本、AI agent 用的是同一批动词。
2. 所有 `-cli.exe` 均内置 **MCP server**（`mcp` 子命令），这是 AI 接入的官方通道。

**通用排障**：应用打不开（闪退）多半是显卡驱动问题，改用 Vulkan 后端启动：

```powershell
$env:WGPU_BACKEND = "vulkan"
& .\deckcraft.exe          # 换成任意 app
Remove-Item Env:WGPU_BACKEND
```

## 二、AI 接入（总纲）

> **现成工具**：`ai-agent\craft_agent.py` 已把下面"方式 A"写成可运行脚本（零第三方依赖，Python 3.12 实测）。
>
> ```powershell
> # 0) 先启动你的 llama.cpp server（OpenAI 兼容，本脚本默认连 http://127.0.0.1:8080/v1，可用 --base-url 改）
> # 1) 看某应用的 MCP 工具清单
> python ai-agent\craft_agent.py --list-tools --app deckcraft
> # 2) 下任务，让大模型自己调用工具完成
> python ai-agent\craft_agent.py --app deckcraft --task "新建3页PPT介绍北京，标题页+两页内容，保存为 workspace\bj.deckcraft 并导出 pptx"
> python ai-agent\craft_agent.py --app wordcraft --task "写一份一周健身计划 docx，含表格"
> python ai-agent\craft_agent.py --app photocraft --interactive   # 交互聊天模式
> ```
>
> 说明：13 个应用中 12 个开箱即用；`lightcraft` 走 `--demo` 示例图库（388 个工具，注意上下文长度），要用自己的图库改脚本里 `--library`；`cadcraft` 需要先开 GUI（脚本会自动 `--launch`）；`filmcraft` 无 MCP，自动化用 `filmcraft-cli run 脚本.jsonl`。agent 的文件读写被限定在 `ai-agent\..\workspace\`（可用 `--roots` 改）。

Craft 应用本体**不含 AI 生成功能**（纯本地编辑器）。把 AI 接进来有三条路，按推荐顺序：

### 方式 A：本地 LLM 经 MCP 直接驱动应用（核心玩法）

每个 `-cli.exe` 都是一个 MCP server。你已有的 llama.cpp（OpenAI 兼容 server）作为"大脑"，MCP 客户端壳负责把模型的工具调用转发给应用。

**1) 无窗口模式（headless，适合批量任务）**

```powershell
# 以 deckcraft 为例：在 MCP 客户端里这样配置
d:\models\tools\storytold-ArtCraft\apps\deckcraft\deckcraft-cli.exe mcp
```

MCP 客户端配置（以 Claude Desktop / Cline / 任何支持 MCP 的 agent 的 JSON 为例）：

```json
{
  "mcpServers": {
    "deckcraft": {
      "command": "d:\\models\\tools\\storytold-ArtCraft\\deckcraft\\deckcraft-cli.exe",
      "args": ["mcp", "--automation-read-root", "D:\\works\\in", "--automation-write-root", "D:\\works\\out"]
    }
  }
}
```

> `--automation-read-root/--automation-write-root` 限定 agent 能读写哪些文件夹，安全绳，建议 always 配。

**2) 驱动已打开的 GUI（适合"边看边改"）**

```powershell
# 先开应用并开控制端口
.\deckcraft.exe --control 7990
# 再让 cli 的 MCP 连上去
.\deckcraft-cli.exe mcp --connect 7990
```

各应用 GUI 控制端口：

| 应用 | 端口/方式 | | 应用 | 端口/方式 |
|---|---|---|---|---|
| deckcraft | `--control 7990` | | wordcraft | `--control 7981` |
| vectorcraft | `--control 7979` | | lightcraft | `--control 7980` |
| designcraft | `--control 7979` | | filmcraft | `--control 9876` |
| cadcraft | `--control 7979` | | effectcraft | `--control 9877` |
| photocraft | `--control`（令牌文件认证） | | pdfcraft | `--control <token.json>`（UI 级控制） |

**3) 接上你的 llama.cpp**

llama.cpp server 本身不说 MCP，需要一个"agent 壳"把两者粘起来（如 Claude Code、Cline、open interpreter，或自己写 20 行循环）。最小自写示例（Python，OpenAI 兼容 + 命令直驱）：

```python
# 思路：把 <app>-cli commands 的输出塞进 system prompt，
# 让 qwen/deepseek 输出命令 JSON，本地 exec 执行，循环到任务完成。
import json, subprocess, urllib.request

LLM = "http://127.0.0.1:8080/v1/chat/completions"   # 你的 llama.cpp
CLI = r"d:\models\tools\storytold-ArtCraft\apps\deckcraft\deckcraft-cli.exe"

catalog = subprocess.run([CLI, "commands"], capture_output=True, text=True).stdout
messages = [{"role": "system",
             "content": "你是 PPT 助手。只能用以下命令（JSON）：\n" + catalog}]

while True:
    user = input("你：")
    messages.append({"role": "user", "content": user})
    req = urllib.request.Request(LLM, json.dumps({"messages": messages, "temperature": 0.2}).encode(),
                                 {"Content-Type": "application/json"})
    reply = json.loads(urllib.request.urlopen(req).read())["choices"][0]["message"]["content"]
    for cmd in json.loads(reply):                      # 模型返回 [{"cmd": "...", "params": {...}}, ...]
        r = subprocess.run([CLI, "run", "--cmd", f'{cmd["cmd"]}={json.dumps(cmd["params"], ensure_ascii=False)}',
                            "--save", "out.deckcraft"], capture_output=True, text=True)
        print(r.stdout)
    messages.append({"role": "assistant", "content": reply})
```

### 方式 B：纯脚本批处理（不需要 LLM，最稳）

所有 `-cli.exe` 的 `run`/`exec`/`convert` 子命令就是为此设计的，适合把"LLM 离线生成 → CLI 落地"拆成两步。见下文各应用的"常用命令"。

### 方式 C：图像生成用 ComfyUI，文件流转粘合

你已有 ComfyUI（8GB 显存独占）。生成与编辑的分工：

```
llama.cpp 写文案/大纲 ──┐
                        ├→ ComfyUI 出图 (PNG) ──→ photocraft 修图 ──→ deckcraft/designcraft 排版
llama.cpp 写提示词 ─────┘
```

**显存纪律**：ComfyUI 与本地 LLM 大模型同时占显存会 OOM，跑 ComfyUI 前先停 LLM server（或反之）；MOSS-Music 等独占进程同理。

### ArtCraft 旗舰（MSI）的 AI

ArtCraft 本体内置 62 个模型目录（图像 16 / 视频 25 / 音频 5 / 3D 网格 11 / 世界 5，含 Nano Banana、FLUX、Seedream、Kling、Veo、Sora 等），走云端 provider API key 按量付费。其 AI 接入层 `craft-ai-integrations`（开源）支持添加**自定义 OpenAI 兼容连接**——可把 base URL 指到 `http://127.0.0.1:8080/v1`（你的 llama.cpp，允许 loopback HTTP），也能把图像生成指向本机 ComfyUI 的 API。装好后在 Settings → AI Providers 里配置。

## 三、各工具使用方法

> 通用套路：`xxx-cli commands [过滤词]` 列出全部命令，`xxx-cli describe <命令id>` 看参数。以下只列最常用的。

### 1. photocraft（修图，PS 对标）

- **格式**：`.pcraft`（原生）、PSD（含图层）、PNG/JPG/TIF/WebP/EXR/TGA/DPX
- **GUI**：`photocraft.exe`，图层/蒙版/调整层。`photocraft --control` 还提供 UI 级控制通道（点按、截图）
- **CLI**：

```powershell
# 查看文档结构（含图层树 JSON）
photocraft-cli info photo.psd
# 格式转换（TIFF 保图层要加 --tiff-layers）
photocraft-cli convert in.psd out.jpg --quality 90
# 无头执行引擎命令（--new 可从零建文档）
photocraft-cli run photo.psd --cmd <id> --params '<json>' --out out.png
# 批处理：整目录跑动作（支持 Photoshop 的 .atn 动作文件！）
photocraft-cli batch --actions my.atn --action "水印" --in .\原图 --out .\成品 --format jpg
```

### 2. lightcraft（RAW 图库，LR 对标）

- **GUI**：`lightcraft.exe`，图库 + 非破坏 RAW 编辑；`--control 7980` 开自动化
- **CLI**（无头图库开发流程）：

```powershell
# 导入 → 调参 → 自动优化 → 导出，一条龙
lightcraft-cli run --import D:\Photos\a.jpg `
  develop.set control=light.exposure value=0.7 `
  develop.auto `
  app.export path=D:\out\a.jpg longEdge=1600
# 常驻图库模式
lightcraft-cli run --library D:\PhotoLib --import D:\Photos ...
```

### 3. vectorcraft（矢量，AI 对标）

- **GUI**：`vectorcraft.exe --control 7979` 开自动化

## 四、下载与更新备注

1. 所有包来自 `https://github.com/storytold/<repo>/releases/download/<tag>/<file>`；每个 release 附 `SHA256SUMS.txt`，介意可自行 `Get-FileHash` 校验。
2. `_packages\` 是安装包缓存（约 990 MB），确认全部应用能启动后可整目录删除腾空间。
3. 更新极频繁（几乎日更），版本策略：稳定压倒一切——`_download.ps1` 里锁定的版本即当前安装版本，升级前先看该 repo 的 release notes 是否有 breaking change。
4. 各应用 `--help`、`commands`、`describe` 是自助文档三件套；更深入看各目录 `README.md`（英文，但含全部细节）。
