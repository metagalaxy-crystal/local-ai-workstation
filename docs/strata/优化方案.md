# Strata 生成速率优化方案（v1 · 待审核）

> 日期：2026-10-18 ｜ 基线：实测约 28 tok/s（中文对话）
> 原则：每项改动都来自官方文档或本机日志的明确提示；一次只改一项、改前备份、改后实测对比；数据不达预期即回退。

## 一、当前状态诊断（来自 strata-iq2_xs.log 的实测证据）

| 发现 | 日志原文 | 影响 |
|---|---|---|
| ① 大页内存被系统拒绝 | `large pages refused for 35,456,548,864 B (VirtualAlloc error 1314); using 4 KB pages` | 约 33GB 专家权重用 4KB 小页管理，内存访问效率低 |
| ② 显存余量告急 | 启动后仅剩 `740 MiB`，请求开始时 `461 MiB`（官方警戒线 1024 MiB） | 显存过满时驱动会把 GPU 内存换页到内存，速度可暴跌至个位数 tok/s（官方 issue #781 实测 7 倍差距） |
| ③ 专家缓存偏小 | `expert cache auto -> 512 slots` | 缓存越少，越多专家要走 PCIe 从内存读 |
| ④ CPU 工作线程为估算值 | `13 CPU expert workers`（setup 估算，未实测校准） | 带 E 核的 14700 上，线程数并非越多越快 |

## 二、优化项（按顺序执行，每项独立验证）

### A1. 启用大页内存 ⭐ 预期收益最大

- **操作**：管理员 PowerShell 运行官方脚本 `tools\windows\enable_large_pages.ps1`（给当前账户授予"锁定内存页"权限），然后注销并重新登录（或重启）
- **依据**：官方文档 #1412；当前 33GB 权重全部退化为 4KB 页
- **风险**：无（仅授予账户权限）；生效需要重新登录一次
- **验证**：重启服务后日志不再出现 `large pages refused`

### A2. 关闭占显存的后台程序（腾出显存给专家缓存）

NVIDIA Overlay、ChatGPT 桌面版、Edge 硬件加速、TeamViewer/ToDesk/AweSun 等合计占约 1.9GB 显存。每腾出 ~256MB ≈ 多 128 个缓存槽位。

- **操作**（按需选择）：关闭 NVIDIA App 游戏内覆盖层；退出 ChatGPT 桌面版；远控软件三选一保留
- **风险**：无，随时可恢复
- **验证**：`nvidia-smi` 空闲占用下降；启动日志 `VRAM free` 行数值上升

### A3. 提高显存预留 `--vram-reserve-mib 700 → 1280`

- **操作**：`START-HERE.bat --setup --vram-reserve-mib 1280`，重启服务
- **依据**：官方日志在本机明确建议 `Add --vram-reserve-mib 1280`
- **注意**：会缩小专家缓存（防暴跌换稳定），应与 A2 配合执行
- **验证**：重启后 `WARNING: only N MiB of VRAM free` 不再出现

### B1. 官方校准 `--calibrate`（一次约 15-30 分钟）

- **操作**：`START-HERE.bat --calibrate`，实测本机最优 `--pool-workers`、`--pcie-frac`、`--spec-min-p`、自适应换出参数
- **依据**：官方文档——校准只保留实测快 3% 以上的设置，结果按"本机+模型"记忆
- **风险**：期间机器繁忙，可能卡顿 1-2 分钟；完成后自动以最优配置启动
- **验证**：校准后用同一测试对话对比 tok/s

### C1. 手动实验：CPU 任务粒度 `--pool-tasks 192`

- **操作**：在 `strata-iq2_xs.json` 的 args 中加入 `"--pool-tasks", "192"`（如无改善即删）
- **依据**：官方文档——带 E 核的 CPU 增加任务数可减少核间不均衡
- **风险**：低；无改善则删掉恢复默认

### C2.（可选）学习型专家档案 `expert_profile_save`

- **操作**：配置加入 `"expert_profile_save": "expert-profile-learned.bin"`
- **依据**：官方 #477——固定类型文本实测 +13~19%（Arc 卡数据，本机待实测）
- **风险**：无（opt-in）；档案文件仅存本机

## 三、统一测试方法（保证数字可比）

每项改完都跑同一条测试：固定中文提示词、max_tokens 256、连续 3 次取中位数，记录 `predicted_per_second`。全程关闭其他大程序。

## 四、不做的事（避免负优化）

| 不做 | 原因 |
|---|---|
| 降低 reserve 到 0 增大缓存 | 官方 #781 实测：显存打满反而 7 倍减速 |
| 开并发 `--parallel` | 多路摊薄单请求速度，与目标相反 |
| 升更高量化档（IQ3_XXS） | 权重更大、内存带宽不变，只会更慢 |
| `--draft-vocab en` | 英文草稿词表省 200+ MiB 显存，但降低中文推测解码接受率，中文场景负优化 |
| 超频显卡/CPU | 不稳定风险高 |

## 五、执行顺序与预期

1. **A1 大页 → A2 腾显存 → A3 调预留**（一次重启验证全部）→ 测速
2. **B1 校准**（自动找最优线程/参数）→ 测速
3. 视结果决定 C1、C2

> 大页与显存优化的具体增幅官方未给本机可比数字，"预期"均以第三节实测为准；B1 校准由官方流程保证"只保留更快 3% 以上"的设置。
