# 本地模型工具调用能力测试报告

> 测试环境：llama.cpp 0.5.0-dev（`--jinja`，ctx 8192）· Windows · 8GB 显存 · 2026-10-19（2026-10-20 增补 Nemotron-3-Nano-Omni-30B 与 LFM2-24B-A2B，均用 Strata 式 MoE 卸载参数）
> - **A** = OpenAI 原生 tools 协议（单调用，验证模型能否发出合规 tool_calls）
> - **B** = JSON 提示词模式（无 tools 字段的多轮决策，agent 的降级方案）
> - **C** = 真实 MCP 端到端（deckcraft：新建演示文稿→加一页标题→按绝对路径保存，验证文件落盘）
>
> ⚠ 第一轮 C 测试曾全军覆没，事后查明是**测试指令的锅**：让模型用相对路径保存，而 Craft 的 automation 安全层只接受 write root 内的绝对路径。修正指令后重测（`-fix` 行），结果如下表。

## 关键发现

1. **路径教训**：Craft automation 层拒绝相对路径/越界路径，报 `automation path rejected`。已把"必须用绝对路径"写进 `craft_agent.py` 的系统提示词，所有模型都能过这关。
2. **"会调工具"≠"能干活"**：所有模型的单步工具调用（A）基本都行；差距在多步规划+自我纠错（C）。修正指令后 3B 也能完成 3 步任务，说明**任务指令的精确性对小模型影响巨大**。
3. **Qwen3.6 是思考模型**：必须关思考链（脚本已在 API 请求里带 `enable_thinking: false`），否则每步先想几千 token，CPU offload 下单步要几分钟。
4. **llama.cpp 偶发 500/400**：LFM2.5 首跑 C 撞 500、Nanbeige 重跑 B 撞 400，重试即恢复，属偶发，agent 循环里已有异常兜底。
5. **B 测试"3 轮未收尾"**：多个模型在 JSON 模式下持续输出调用而不用 `{"answer":...}` 结束——是提示词约定偏弱，不影响原生模式；已在 agent 的 max-steps 机制里兜底。
6. **LFM2-24B 的 agent 短板（2026-10-20 两轮复测确认）**：A 原生单步没问题，但 B 模式稳定复现 `KeyError: 'tool'`（模型输出的 JSON 不带 `tool` 键），C 模式两轮分别跑满 7 步收尾/8 步上限，均未落盘——**agent 能力与参数量不成正比**，同家族 8B 的 LFM2.5-8B 反而 3/3 全过。结论：当写作/摘要模型用（bench T4 4.5），别当 agent。
7. **Nemotron-3-Nano-Omni-30B agent 全过（3/3）**：C 模式 3 步完成落盘，是继 Qwen3.6-35B 后第二款可胜任 agent 大脑的本地模型，且自带视觉/音频多模态；B 模式同样"3 轮不收尾"，与其它模型弱点一致。两款测试均用 Strata 式 MoE 卸载参数（lfm24b `--n-cpu-moe 21`、nemotron `--cpu-moe`，均 `--load-mode none -t 6`）。
