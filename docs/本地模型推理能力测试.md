# 本地模型硬推理能力测试

> 环境：llama.cpp 0.5.0-dev · Windows · RTX 5060 Laptop 8GB + i9-13900HX · 2026-10-20
> 方法：10 道有确定答案的硬推理题（[bench_reasoning.py](bench_reasoning.py)），**自动判分 + 人工复核全部 ✗ 项**；temperature 0.3（主 bench 为 0.7）；max_tokens 1500（**答不完即判负**——推理啰嗦本身就是可用性缺陷）；各模型启动参数与中文卷一致。
> 与主 bench 的关系：主 bench T2（鸡兔同笼）9 款全对、无区分度；本卷题目难度上调数个档位，专测多步推理深度。结果目录 `bench_results/<模型>_reasoning/`。

## 四、关键发现

1. **Nemotron 的推理能力是本地第一梯队，且"性价比"最高**：10/10 全对，每题平均只花 16.2 s、最省 token（q04 仅 160 tok 就收尾）。结合英文卷的 4.0/4.3/4.0 与中文卷的平平表现，结论清晰：**Nemotron 的问题是中文表达与输出纪律，推理硬件一点不虚**。它答 q09（过河）用了 1332 tok、37.7 s，是它最长的一题，但仍推完了。
2. **Qwen3.6-35B 唯一双满分模型**（推理 10/10 + 工具调用最干净），"本地综合第一"的坐垫进一步坐实；弱点是 q10 推到 1500 token 才收尾——能推对但过程啰嗦。
3. **LFM2-24B 与 LFM2.5-8B 推理打平（9 vs 9）**——直接回答了"24B 是不是被设备限制了"：同卷同参数下，24B 的优势体现在**答案更简洁**（每题 169–569 tok vs 8B 的 358–1245 tok）和主 bench 的写作/摘要质量（4.0/4.5 vs 1.5/1.5），而**推理深度与 8B 无差异**。这正是 MoE 的特性：激活 2B 决定了推理深度，仓库 24B 决定知识容量。设备限制的是速度（34 vs 222 tok/s），不是能力。
4. **DeepSeek-R1 的 5/10 是"思维链失控"导致的工程性溃败**：`enable_thinking:false` 对 R1 模板无效（llama.cpp jinja 不支持），它把 1500 token 预算全部烧在思考过程里，10 题中 5 题推理中途被掐断——截断处全是"为了计算""所以，我需要"这类未完成的思考。**它不是不会算，是停不下来**。16.5 tok/s 的速度让这个问题雪上加霜（每题约 90 s 才截断）。给 R1 分配更大预算或换支持 thinking 开关的推理栈才有意义。
5. **Ornith 同病相怜但轻一些**：4 题截断全因反复试写草稿（与中英文卷"思维链霸屏"一致），能推对 6 题说明底子不差，输出纪律毁了它。
6. **lfm 在推理卷又一次用英文答题**（q09 整题英文）——中文指令下的语言漂移问题在第三次测试中复现（中/英/推理卷），这是 LFM 家族的稳定特征。
7. **q06（可变默认参数）是最好的"深度探针"**：不需要任何知识，纯考对 Python 语义的精确理解，3 家栽在这里（lfm答[1]、ornith截断、deepseek截断），与参数量完全无关。

## 五、结论与选型建议（推理场景）

| 场景 | 首选 | 理由 |
|---|---|---|
| 硬推理 / 数学 / 代码 | **Nemotron-30B** 或 **Qwen3.6-35B** | 双满分；Nemotron 更省 token 更快收尾，Qwen 综合最稳 |
| 推理 + 低资源 | **Nanbeige4.2-3B** | 3B 拿 9/10，速度 26-38 tok/s，无短板 |
| 推理 + 速度（交互式） | Qwen2.5-VL-7B / MiniCPM | 67/275 tok/s，9 题以内正确率够用 |
| 不推荐硬推理 | DeepSeek-R1-8B（本机栈）、MiniCPM | R1 思维链失控截断；MiniCPM 规划题崩 |

> 复现：`python run_reasoning.py [label...]`（自动起服/跑/杀，断点续跑）；单模型 `python bench_reasoning.py --preset <label>`。判分规则修正后已通过正/反向自测（10/10 命中正确答案、0 误判典型错误答案）。
