# 本地模型英文基准测试

> 环境：llama.cpp 0.5.0-dev · Windows · RTX 5060 Laptop 8GB + i9-13900HX（32 线程）· 2026-10-20
> 提示词：**英文**（`bench_universal.py --lang en`）· 采样温度 0.7（与中文卷一致）· 各模型启动参数同中文卷（`models.json` 推荐值）
> 中文卷：同脚本、同参数、中文提示词，见 **《云端vs本地模型对比.md》**。两份**分开记录、不可直接横比**（题面不同、T5 文学题不同）。
> 评分：人工评分沿用中文卷**同一把尺（1–5 分制）**；本卷把 T7 拆成 T7a 微小说 / T7b 命名**两列单列**（中文卷只列两题均值）。

## 一、为什么要单独做英文卷

起因：Nemotron-3-Nano-Omni 是英文语料为主的模型，中文卷给它写作只打 3.5 分，且探针阶段偶发整段英文作答——中文试卷可能**系统性地压低了它的分数**。本卷用同一套测试、换成英文题面，把"语言劣势"从"能力"里剥离出来。

**边界**：英文卷不能和中文卷的 9 款成绩直接横比（题面、T5 文学题都不同），它只回答两个问题——① 各模型在英文下自身表现如何；② 换成母语后，谁的名次会变。

## 二、英文题集与方法

| 项 | 英文卷做法 | 与中文卷的关系 |
|---|---|---|
| T4 长文 | 丝绸之路**英文版**（同主题、同结构，约 1800 字符） | 同内容不同语言，可做语言对照 |
| T5 知识 | 光速、HTTP 404 两题事实不变；文学题由《红楼梦》→ **《傲慢与偏见》** | 英文卷里问中国古典名著，测的是知识面而非英文能力，会误杀非中文模型 |
| T2 数学 / T3 代码 | 题面译英文，**判分逻辑不动**（真跑代码 / 数字判定） | 保持与中文卷同口径 |
| T6 多模态 | 提问改英文，测试图同一张 | 仅 4 款带 mmproj 的模型参测 |
| T0 速度探针 | 英文探针题，2 次取低值 | 速度与语言无关，仅记录 |

执行方式：`run_en_bench.py` 对 9 款模型依次「起服 → 跑 T0–T7 → 杀进程」，结果落 `bench_results/<模型>_en/`，全程 **rc=0，无失败、无跳测**。

## 六、中英双卷对照（本卷核心）

| 模型 | T1 中→英 | T4 中→英 | T7 均值 中→英 | 变化解读 |
|---|---|---|---|---|
| **Nemotron-30B** | 3.5 → **4.0** | 4.5 → 4.3 | 3.8 → **4.0** | **唯一显著上升**：中文卷确实压低了它 |
| LFM2.5-8B | 1.5 → 1.8 | 1.5 → **1.0** | 2.0 → 3.1 | 持平偏下，输出卫生问题两卷都在 |
| DeepSeek-R1-8B | 3.5 → 3.8 | 2.5 → **4.0** | 3.5 → 2.5 | T4 大幅改善（英文不再撞 max_tokens 截断） |
| Qwen3.6-35B | 5.0 → 4.5 | 5.0 → 4.3 | 4.8 → 4.1 | 微降（英文题更长/要求更细），仍居第一 |
| Nanbeige4.2-3B | 4.5 → 4.3 | 4.5 → 4.5 | 4.0 → 3.8 | 基本持平 |
| Qwen2.5-VL-7B | 4.0 → 3.8 | 4.0 → 3.5 | 2.8 → 2.0 | 命名题在英文卷同样失守 |
| Ornith-1.0-9B | 2.0 → 1.5 | 1.5 → 1.0 | 2.8 → 2.5 | 输出卫生更差 |
| MiniCPM-V-4.6 | 3.5 → **1.5** | 2.5 → 2.8 | 2.0 → 1.5 | T1 恶化成构思独白 |
| LFM2-24B-A2B | 4.0 → 4.0 | 4.5 → 4.0 | 3.8 → 2.6 | 写作摘要稳定，创造力在英文卷更弱 |

**结论（回答"换英文会不会翻盘"）**：

1. **不会翻盘，但差距被抹平了一部分。** Nemotron 提升 0.5 分（T1 3.5→4.0），说明中文试卷确实"欺负"了它——但它补齐语言后是 **4.0 / 4.3 / 4.0**，追平 Nanbeige、LFM2-24B，仍**排在 Qwen3.6-35B（4.5 / 4.3 / 4.1）之下**。它的真问题不是语言，而是**输出纪律**（T5 漏判、工具调用不收尾，同一毛病）。
2. **±0.5 分内的波动多半是人工评分噪声**，真正显著的变化只有三处：Nemotron ↑、DeepSeek 的 T4 ↑（截断消失）、MiniCPM/Ornith/LFM 的 ↓（输出卫生）。
3. **"输出卫生"与语言无关，是模型固有缺陷**：LFM2.5-8B、Ornith、MiniCPM 在英文卷把思维链 / 构思独白直接吐进正文（Ornith 的 T7a 1200 token 全是反复试写、成品为零；MiniCPM 的 T1 699 词全在讲"我要怎么写"）。中文卷同样存在，英文卷更严重。
4. **T7b"名字 + 一句解释"是普遍失守点**：DeepSeek / Qwen2.5-VL / MiniCPM / LFM2-24B 四家只给裸名字、解释全丢；写全的 Nanbeige / LFM2.5-8B / Ornith / Nemotron / Qwen3.6 反而质量都不错。
5. **9 款全部用英文作答，无一串语言**。中文卷里 MiniCPM/LFM 曾在中文题擅自改用英文，"语言纪律"问题在英文卷自然消失。

## 七、判分规则误判与坑（可信度说明）

1. **T5 关键词过于字面 → 2 处误判**：MiniCPM 答光速用 LaTeX `3\times10^5`（数值正确）、Nemotron 答 404 用 "could not be found"（语义正确），都因不匹配连续关键词被判 ✗。**人工复核后英文卷 T5 实为 9/9 全对**（自动口径 7/9）。
2. **中文卷同一根因**：Nemotron 中文卷 T5 的 2/3 也非能力问题——404 题它答对了，失分在光速题用了千分位逗号（`299,792`/`300,000`）不匹配 `300000`。
3. **T3 存在"侥幸通过"**：LFM2-24B 用 `Counter.most_common(k)`，未实现"平局按数值升序"，只因测试用例未触发平局而自动 PASS。
4. **T3 的两处 ✗ 是模型问题，非误判**：DeepSeek 输出全是分析散文（代码一字未出）；MiniCPM 逻辑正确但丢了 `from collections import Counter`（NameError）。二者与中文卷失败模式一致。
5. **T0 探针波动大**（见第三节 ⚠），排序参考价值有限。

## 八、工具调用（语言无关，本卷未重跑）

工具调用测试考的是协议遵循与多步规划，与题面语言无关，故未在英文卷重跑。相关结论见 **《工具调用测试报告.md》**：本地真正"干净利落"的只有 Qwen3.6-35B 与 LFM2.5-8B 两家；Nemotron 的 3/3 属**弱通过**（3 步落盘但全程未主动收尾），LFM2-24B 为真失败（B 崩 `KeyError: 'tool'`、C 两轮 7/8 步未落盘）——与本卷"输出纪律"结论互相印证。
